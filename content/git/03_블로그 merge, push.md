## Quartz 블로그 작성

블로그를 보다시피 저는 Quartz를 이용해서 간단하게 블로그를 작성하고 있습니다.

앞에서 언급헀드시 저는 매일 블로그를 업데이트를 하는 것은 과도하다고 생각했습니다.
이유는 저는 블로그 자체를 기록하는데 의미를 두었습니다.
또한 공부하면서 배웠는데 테스트하고 배포 용은 구분 되어 있어야 한다고 했던게 생각나서 입ㄴ다.

앞에서 보셨드시 에러가 발생할때 마다 배포하다고 생각해보세요
실제로는 제가 그냥 배포를 진행한다고 해서는 문제는 없습니다.

하지만 실제로 개발자 직군에서 에러 있는 웹페이지를 테스트도 하지 않고 배포한다고 생각해보세요... 끔찍하죠

그래서 생각했습니다.

branch를 분리하자

매일 작성하고 데이터를 저장하는 Test
매일 작성한 내용을 마지막 검수하고 블로그에 업로드 하는 v4
그러다 보니
merge, push등 깃허브 문법이 생각 났습니다

### 노트 작성 계기

바로 들어갔을 때에는 Production이 없고 preview만 되어 있었습니다.
많이 놀랐고 잘못했나 걱정도 되었고 내가 터미널에서 git을 해서 문제가 발생했나
많은 생각을 하게 되었습니다. 그러다보니 git checkout v4를 진행 후
다시 git push를 진행했습니다.

이것저것을 많이 찾아보고 했습니다.
해프닝이라고 생각하니까 웃겼고 적어 놓으면 다음에 도움이 될거 같아서
이렇게 작성하게 되었습니다.

해프닝의 결과는 제가 한국이이였다는 사실입니다.
조금 지나고 보니까 production이 생겼습니다.

찾아보니까 웹페이지 제작, 배포하는데 시간이 걸렸던 것이였습니다.

test를 git push를 진행하고 바로 v4에가 넘어가서 merge를 하니까
test 웹페이지를 만들고 v4 배포하는데 까지 시간이 걸렸던 것입니다.
