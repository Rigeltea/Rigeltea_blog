Lesson 2. 작은 구간에서 큰 구간으로 확장되는 DP

기본 문제에서는 단계별 학습을 위해 각 문제가 하나의 기본개념과 짝을 이룹니다. 연습 문제와 테스트 문제에서는 쉽게 복습할 수 있도록 모든 개념이 함께 제공됩니다.

## 작은 구간에서 큰 구간으로 확장되는 DP

다음 문제는 어떻게 해결해볼 수 있을까요?

```
n개의 정수가 주어졌을 때, 인접한 2개의 정수를 골라 합쳐 
새로운 하나의 수로 만들어 주는 것을 수가 하나 남을때까지 반복하려고 합니다. 

이때 2개의 수 a, b를 합치게 되면 더 큰 수 하나만 남게 되고 
이때 발생하는 비용은 a + b가 됩니다.

예를 들어, 순서대로 40 30 10 50이 주어진 경우에 대해 생각해보겠습니다.

만약 처음 (40, 30)을 합치면 40 10 50이 되고 이후 10 50을 합치고 
남은 40 50을 합치면 50 하나만 남게 됩니다. 
이 과정에 드는 총 비용은 70+60+90 = 220이 됩니다.

하지만 처음 (30, 10)을 합치면 40 30 50이 되고 이후 40 30을 합치고 
남은 40 50을 합치면 50 하나만 남게 됩니다. 
이 과정에 드는 총 비용은 40+70+90 = 200이 됩니다.

합치는 순서를 잘 정하여 드는 총 비용을 최소로 해보세요.
```

어떤 순서로 합치는게 최선일지 판단하기가 어려운 문제입니다. 하지만 합치는 과정을 직접 시뮬레이션 하지 않고, $[i, j]$ 구간에 있는 수들을 하나로 합치기 위해 필요한 최소 비용에 집중하여 생각해보면 동적계획법을 이용해 이 문제를 해결할 수 있습니다.

`dp[i][j] = [i, j] 구간에 있는 수들을 전부 하나로 합치기 위해 필요한 최소 비용` 으로 정의해봅시다. 그러면 $[i, j]$ 까지의 수들이 전부 하나로 합쳐지기 바로 직전 상황을 생각해보면, 아래와 같이 $[i, k], [k +1, j]$ 구간이 먼저 합쳐져 있는 상황에서 최종적으로 남은 2개의 수가 다시 합쳐진 형태를 띌 것입니다.

![](https://contents.codetree.ai/problems/1297/images/introductions-74d13cb3-0247-41d0-b01b-0308f7fefbb6.png)

여기서 흥미로운 사실은 $[i,j]$ 까지의 수들이 합쳐져 나온 수 $Merged[i][j]$ 는 **합쳐지는 순서에 관계 없이 항상 동일한 값을 갖게 된다는 것입니다.** 그 이유는 문제 특성상 두 수가 합쳐졌을 때 남게되는 수는 더 큰 수 이기 때문에 $[i, j]$ 사이의 수들이 전부 합쳐지게 되었을 때 남는 수는 구간 내 있는 수들 중 최댓값에 해당하는 수가 되기 때문입니다.

즉, $Merged[i][j]$ 는 아래와 같이 $O(N^2)$ 에 미리 전처리를 통하여 각 구간에 대해 최댓값을 구해주는 것으로 계산이 가능합니다.

```python
n = 4
arr = [0, 40, 30, 10, 50]
# merged 값을 미리 계산합니다.
# [i, j]까지 수를 합쳤을 떄의 결과를 미리 계산합니다.
for i in range(1, n + 1):
    merged[i][i] = arr[i]
    for j in range(i + 1, n + 1):
        merged[i][j] = max(merged[i][j - 1], arr[j])
```

이제 $DP[i][j]$ 에 대한 점화식을 세워보겠습니다. 하나로 합쳐지기 직전에는 꼭 $[i, k], [k + 1, j]$ 구간의 형태로 합쳐져있는 상황에서 최종적으로 한번 더 합치는 작업을 진행하여 $[i, j]$ 사이에 있는 모든 수가 합쳐지게 된다고 했습니다. 이때 어느 위치를 k로 해야 최선일지를 알 수 없기에, $[i, j - 1]$ 사이에 있는 모든 k에 대해서 전부 조사하여 그 중 비용이 최소가 되는 경우를 골라야 합니다.

k가 정해져 있다는 가정하에서는 DP의 특성상 이미 구간 $[i, k]$ 사이의 수들을 합치는데 필요한 최소 비용 값이 $DP[i, k]$ 에 들어있으며, 마찬가지로 구간 $[k + 1, j]$ 사이의 수들을 합치는데 필요한 최소 비용은 $DP[k + 1, j]$ 에 들어있습니다. 이제 두 구간으로부터 나온 2개의 수인 $Merged[i][k]$ 와 $Merged[k+1][j]$ 을 합치면 $[i, j]$ 구간 내 모든 수가 합쳐지게 되며 이때 추가로 발생하는 비용은 남은 두 수의 합인 $Merged[i][k] + Merged[k+1][j]$ 가 됩니다.

따라서 점화식은 아래와 같이 세워지게 됩니다.

$$
\begin{aligned}
DP[i][j] = \min_{\substack{i\le k < j}} DP[i][k] + DP[k+1][j] + \\
Merged[i][k]+Merged[k+1][j]
\end{aligned}
$$

초기 조건은 지극히 당연한 상황에 해당하는 수가 하나만 있는 경우입니다. 즉, 구간 $[i, i]$ 에 대해서는 수를 합칠필요 없이 이미 수가 하나만 있기 때문에 비용 0에 해당하는 $DP[i][i] = 0$ 이 됩니다.

이 문제에서 중요한 부분은 **큰 구간에 대한 DP값이 채워지기 이전에 작은 구간에 대한 DP값이 먼저 채워져야 한다는 것입니다.** 일반적으로 2차원 DP의 경우 i, j가 둘 다 증가하는 순으로 채워지면 작은 문제에 대한 답이 먼저 채워져있음을 보장할 수 있었습니다. 하지만 이 문제에서는 점화식이 구간의 크기에 영향을 받게 되기 때문에, **구간의 크기가 커지는 순으로** DP값이 채워져야만 합니다.

![](https://contents.codetree.ai/problems/1297/images/introductions-c370a198-a426-4674-be7f-b5eb81eaa730.png)

이를 Tabulation을 이용하기 위해서는 아래와 같이 구간의 크기에 해당하는 gap을 먼저 정해주고, 이후 시작점 i를 정해주어 이에 따라 끝점 j가 알아서 정해지도록 하는 것입니다. 이로부터 gap이 작은 구간부터 순서대로 채워지는 것을 보장할 수 있습니다.

```python
for gap in range(2, n + 1):
    # 구간의 시작위치 i를 정해줍니다.
    for i in range(1, n - gap + 2):
        # 구간의 크기와 시작 위치가 정해져 있기에
        # 끝 위치는 자동으로 정해집니다.
        j = i + gap - 1

        # 구간 [i, j]에 대한 탐색을 진행합니다.
        ...
```

이러한 과정을 거쳐 주어진 4개의 수 `40 30 10 50` 에 대한 최소 비용을 구하는 코드를 작성해보면 다음과 같습니다. 문제에서 원하는 답은 n개의 수가 전부 합쳐지기 위한 최소 비용을 뜻하는 $DP[1][4]$ 가 됩니다.

```python
import sys

INT_MAX = sys.maxsize

# 변수 선언 및 입력:
n = 4
arr = [0, 40, 30, 10, 50]

merged = [
    [0] * (n + 1)
    for _ in range(n + 1)
]

# dp[i][j] : [i, j] 구간에 있는 수들을 전부 하나로 합치기 위해
#            필요한 최소 비용을 기록합니다.
dp = [
    [0] * (n + 1)
    for _ in range(n + 1)
]

# merged 값을 미리 계산합니다.
# [i, j]까지 수를 합쳤을 떄의 결과를 미리 계산합니다.
for i in range(1, n + 1):
    merged[i][i] = arr[i]
    for j in range(i + 1, n + 1):
        merged[i][j] = max(merged[i][j - 1], arr[j])

# 최솟값을 구해야 하므로 
# dp 초기값으로 아주 큰 값을 설정합니다.
for i in range(1, n + 1):
    for j in range(1, n + 1):
        dp[i][j] = INT_MAX

# 수가 하나만 남았을 때는 종료되므로
# 추가 비용이 들어가지 않습니다.
# 즉, 구간의 크기가 1인 경우 dp값이 0이 되어야 합니다.
# dp[i][i] = 0이 초기조건이 됩니다.
for i in range(1, n + 1):
    dp[i][i] = 0

# dp는 미리 구해져 있는 작은 문제를 가지고 큰 문제를 풀어야 하므로
# 이러한 유형의 경우 구간을 점점 넓혀가면서 dp값을 채워야만 합니다. 
# 따라서 구간의 크기를 2부터 n까지 증가하게 미리 정해줍니다.
for gap in range(2, n + 1):
    # 구간의 시작위치 i를 정해줍니다.
    for i in range(1, n - gap + 2):
        # 구간의 크기와 시작 위치가 정해져 있기에
        # 끝 위치는 자동으로 정해집니다.
        j = i + gap - 1

        # 구간 [i, j]에 대한 탐색을 진행합니다.
        ...

        # [i, j]가 되기 위해
        # 최종적으로 합쳐지는 두 수가
        # 각각 [i, k], [k + 1, j]로부터 온 결과였을 경우의
        # 최적의 비용을 구해 가능한 경우 중 최솟값을 갱신해줍니다.
        for k in range(i, j):
            cost = dp[i][k] + dp[k + 1][j] + merged[i][k] + merged[k + 1][j]
            dp[i][j] = min(dp[i][j], cost)

# 모든 수를 합치는 데 필요한 최소 비용을 출력합니다.
print(dp[1][n])
```

## Memoization

보통 재귀함수와 캐싱을 이용하여 DP문제를 해결하는 Memoization 방법은 Iteration 기반의 Tabulation보다 더 쉬운 코드를 제공해주지는 않습니다. 오히려 구현 난이도가 더 높은 경우가 많습니다.

하지만 이렇게 작은 구간에서 큰 구간으로 확장되는 형태의 DP 유형의 경우에는 놀랍게도 **Memoization** 방식의 코드로 굉장히 깔끔하게 구현할 수 있습니다.

점화식은 동일하며 결국 1번부터 4번까지의 수를 합쳐야 하므로 $FindMin(1, 4)$ 가 답이 됩니다. Memozation은 특성상 관심있는 값을 계산하기 위해 필요한 값들을 재귀적으로 호출하는 구조이기 때문에 알아서 구간의 크기가 작은 DP값부터 완성시켜줄 것이 분명하므로, 아래와 같이 특별한 처리 없이 깔끔하게 코드 구현이 가능합니다.

```python
import sys

INT_MAX = sys.maxsize

# 변수 선언 및 입력:
n = 4
arr = [0, 40, 30, 10, 50]

merged = [
    [0] * (n + 1)
    for _ in range(n + 1)
]

# dp[i][j] : [i, j] 구간에 있는 수들을 전부 하나로 합치기 위해
#            필요한 최소 비용을 기록합니다.
dp = [
    [0] * (n + 1)
    for _ in range(n + 1)
]

# merged 값을 미리 계산합니다.
# [i, j]까지 수를 합쳤을 떄의 결과를 미리 계산합니다.
for i in range(1, n + 1):
    merged[i][i] = arr[i]
    for j in range(i + 1, n + 1):
        merged[i][j] = max(merged[i][j - 1], arr[j])

# 아직 계산이 되지 않았다는 의미로 -1을 넣어줍니다.
for i in range(1, n + 1):
    for j in range(1, n + 1):
        dp[i][j] = -1

def find_min(i, j):
    # 이미 한번 구해본적이 있다면
    # 값을 바로 반환합니다.
    if dp[i][j] != -1:
        return dp[i][j]

    # 수가 하나만 남았을 때는 종료되므로
    # 추가 비용이 들어가지 않습니다.
    # 즉, 구간의 크기가 1인 경우 dp값이 0이 되어야 합니다.
    # dp[i][i] = 0이 초기조건이 됩니다.
    if i == j:
        dp[i][i] = 0
        return dp[i][i]
    
    # [i, j]가 되기 위해
    # 최종적으로 합쳐지는 두 수가
    # 각각 [i, k], [k + 1, j]로부터 온 결과였을 경우의
    # 최적의 비용을 구해 가능한 경우 중 최솟값을 갱신해줍니다.
    best = INT_MAX
    for k in range(i, j):
        cost = find_min(i, k) + find_min(k + 1, j) + merged[i][k] + merged[k + 1][j]
        best = min(best, cost)
    
    dp[i][j] = best
    return dp[i][j]

# 모든 수를 합치는 데 필요한 최소 비용을 출력합니다.
print(find_min(1, n))
```
