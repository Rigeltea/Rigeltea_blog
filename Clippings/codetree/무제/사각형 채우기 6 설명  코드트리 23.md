Lesson 1. 이진탐색

기본 문제에서는 단계별 학습을 위해 각 문제가 하나의 기본개념과 짝을 이룹니다. 연습 문제와 테스트 문제에서는 쉽게 복습할 수 있도록 모든 개념이 함께 제공됩니다.

## 이진탐색과 순차탐색

우리가 이진탐색을 배운 이유는 순차탐색 보다 더 빠르기 때문일겁니다. 실제로 앞에서 이진탐색을 연습해보면 더 적은 횟수의 연산으로 원하는 값을 찾을 수 있다는 것을 경험 했을겁니다.

그렇다면 실제 이진탐색의 시간복잡도는 어떻게 될까요? 결론만 말하면 $O(logN)$ 입니다.

소스코드를 한번 살펴보겠습니다.

```jsx
function solution(arr, target)
  set left = 0
  set right = arr.size - 1
  while left <= right
    set mid = (left + right) / 2
    if arr[mid] == target
      return mid

    if arr[mid] > target
      right = mid - 1
    else
      left = mid + 1
      
  return -1
```

4번째 줄부터 12번째 줄까지의 루프를 한 번 돌때 마다, 우리가 다루는 구간의 길이(right - left + 1)는 반으로 감소하고, 구간의 길이가 1이 될 때 까지 계속 반복해서 탐색하는 것을 볼 수 있습니다. 즉, 루프는 약 $log_2N$ 번 돌게 됩니다. 루프 내부 연산의 시간 복잡도는 $O(1)$ 이기 때문에, 자연스럽게 시간복잡도는 $O(1 * logN) = O(logN)$ 이 되는 것을 볼 수 있습니다.

| loop 반복 횟수 | 구간의 길이 |
| --- | --- |
| $1$ | $N$ |
| $2$ | $N/2$ |
| $3$ | $N/4$ |
| ... | ... |
| $logN$ | 1 |

이제 이진탐색과 순차탐색을 비교해봅시다. $O(N)$ 과 $O(logN)$ 은 얼마나 큰 차이가 있을까요? 결론만 말씀 드리면 엄청난 차이입니다.

![](https://contents.codetree.ai/problems/498/images/introductions-6c8c1c53-ccdd-4b6c-acba-eca66991169f.png)

다음 그림과 같이, 약 42억개의 원소가 있으면 순차탐색은 그 42억 개의 원소를 모두 체크해야 하지만, 이진탐색을 사용하면 최대 32회의 연산을 통해 원하는 값의 위치를 찾을 수 있습니다! 따라서 기본적으로 값을 찾을 때는 이진탐색을 많이 사용하며, 실제로 이진탐색의 원리를 활용해 값을 빠르게 찾을 수 있도록 하는 자료구조도 존재합니다. (뒤에서 학습할 예정입니다.)

그러나 모든 상황에서 이진탐색이 유리한 것은 아닙니다. 이진탐색이 갖고 있는 단점이라면 반드시 정렬이 되어야 한다는 것입니다. 따라서 배열이 정렬된 상태가 아니라면, 정렬을 하기 위해 추가적인 연산을 필요로 합니다.

- 정렬된 상태에서 이진 탐색: $O(logN)$
- 정렬되지 않은 상태에서 이진 탐색: $O(NlogN + logN)$

정렬을 추가로 진행한다면, 퀵 정렬 같은 알고리즘을 활용했을 때 $O(NlogN)$ 이 추가적으로 사용 되기 때문에 오히려 순차탐색에 비해 느려집니다!

따라서 정렬된 경우엔 반드시 이진탐색을 사용하는 것이 효율적이겠지만, 그렇지 않은 경우라면 이진탐색을 사용하기 전에 한번 더 생각해보아야 합니다. 만약 탐색을 여러 번 진행해야 한다면 이진탐색을 사용하는 것이 좋겠지만, 가장 큰 값을 찾는다거나, 값을 딱 한개만 찾는다면 굳이 이진탐색을 사용할 이유가 없을 겁니다.
