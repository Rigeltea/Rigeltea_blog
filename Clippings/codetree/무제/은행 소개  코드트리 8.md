Lesson 9. Greedy Algorithm

기본 문제에서는 단계별 학습을 위해 각 문제가 하나의 기본개념과 짝을 이룹니다. 연습 문제와 테스트 문제에서는 쉽게 복습할 수 있도록 모든 개념이 함께 제공됩니다.

## 회의실 준비

다음 문제를 살펴봅시다.

```
하나의 회의실이 있고, n개의 회의 요청이 들어왔습니다. 
각 회의의 시작 시간과 끝 시간이 주어져 있으며, 
한 회의가 시작되면 도중에 그만둘 수 없고, 
한 회의가 끝나는 직후에 동시에 다른 회의가 시작될 수 있습니다. 
적절하게 회의 요청을 수락하여 최대로 많은 회의가 진행되도록 만들어보세요.

예를 들어 회의가 [1, 2], [2, 9], [3, 6], [4, 8] 이렇게 4개 있다면
[1, 2], [3, 6] 이렇게 진행하면 총 2개의 회의를 진행할 수 있게 됩니다. 
이보다 더 많은 회의를 진행할 수는 없습니다.
```

이 문제는 어떻게 해결해 볼 수 있을까요?

동적계획법을 이용하여 i번째 시간까지 처리할 수 있는 최대 회의의 수를 갱신하는 식으로 진행하는 것도 가능합니다.

하지만 이 문제를 그리디 알고리즘으로 풀어볼 수는 없을까요?

- 시도 1. **회의 시작 시간** 을 기준으로 오름차순 정렬하여 그리디 알고리즘으로 접근
	이 경우는 다음 예시에서 올바른 답을 구해주지 못합니다. `[1, 2], [2, 9], [3, 6], [6, 8]` 은 시작 시간 기준으로 오름차순 정렬이 되어있는데 이 상황에서 순서대로 겹치지 않게 고르면 `[1, 2], [2, 9]` 가 답이 됩니다. 하지만 최적의 답은 `[1, 2], [3, 6], [6, 8]` 로 3이 되므로 반례가 존재하게 됩니다. 이처럼 반례가 있는 경우라면 그리디 알고리즘을 사용할 수 없습니다.
- 시도 2. **회의 구간의 길이 (끝 시간 - 시작 시간)** 를 기준으로 오름차순 정렬하여 그리디 알고리즘으로 접근
	이 경우는 다음 예시에서 올바른 답을 구해주지 못합니다. `[6, 8], [7, 10], [1, 7]` 은 회의 구간의 길이 기준으로 오름차순 정렬이 되어있는데 이 상황에서 순서대로 겹치지 않게 고르면 `[6, 8]` 단 하나만 고를 수 있게 됩니다. 하지만 최적의 답은 `[1, 7], [7, 10]` 으로 2가 되므로 반례가 존재하게 됩니다. 이처럼 반례가 있는 경우라면 그리디 알고리즘을 사용할 수 없습니다.
- 시도 3. **회의 끝 시간** 을 기준으로 오름차순 정렬하여 그리디 알고리즘으로 접근
	이 경우에는 모든 경우에 대해 올바른 답을 구해주게 됩니다. `시도 1` 에서의 예시에서는 끝 시간 정렬시 `[1, 2], [3, 6], [6, 8], [2, 9]` 가 되므로 순서대로 보며 겹치지 않게 고르면 `[1, 2], [3, 6], [6, 8]` 로 최적의 답인 3이 나오게 되고, `시도 2` 에서의 예시에서는 끝 시간 정렬시 `[1, 7], [6, 8], [7, 10]` 이 되므로 순서대로 보며 겹치지 않게 고르면 `[1, 7], [7, 10]` 이 되어 최적의 답인 2가 나오게 됩니다.

이처럼 회의실 준비 문제에서는 회의 끝시간을 기준으로 오름차순 정렬한 뒤, 순서대로 보며 겹치지 않는 회의를 순차적으로 골라주면 최적의 답을 구할 수 있게 됩니다.

이 방법이 가능한 이유는 현재 상황에서 끝나는 시간이 k인 가장 앞선 회의 보다 이후 k' 시간 때에 끝나는 회의를 선택했을 때, 앞으로 회의에 추가적으로 사용할 수 있는 시간이 항상 더 짧아지기 때문입니다. 따라서 항상 일찍 끝나는 회의를 greedy하게 선택하는 것이 최적이라 할 수 있습니다.

이처럼 회의실 준비 문제는 그리디 알고리즘으로 풀리지만, 어떤 그리디 알고리즘을 사용하는지에 따라 올바른 답을 구해줄 수도 / 없을 수도 있다는 사실을 꼭 기억하셔야 합니다.
